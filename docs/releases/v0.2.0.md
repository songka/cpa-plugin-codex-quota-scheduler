## Codex Quota Reserve v0.2.0

目标宿主：CLIProxyAPI v8.0.27，Linux glibc AMD64 / ARM64。
插件 ID 保持 `codex-quota-reserve`，插件库源地址不变。

### 修复与新增

- 修复达到预留线后只有保护标记、CPA 仍保持启用的问题。新增 `reserve_disable_accounts` 开关，默认关闭，需要在插件设置中显式开启。
- 保留停用所有权及凭据指纹，不接管人工停用账号，不自动恢复已经轮换的凭据。
- 支持主动重置后的恢复：定期查询插件停用的账号，手动刷新可提前检查；两个额度窗口恢复且高于保护线后自动启用。
- 自动估算每请求消耗：至少三个有效样本，最近最多八个样本中位数乘 1.25；默认上下限 0.01%-2%，可配置，最高允许 10%。重置、轮换、无请求及异常数据不参与学习。
- Webhook 地址和 Telegram Chat ID 可直接在插件中配置；设置响应及导出隐藏秘密，留空不会覆盖已保存值。
- 新增定时使用报告、账号开始/停止参与调度及 CPA 停用/恢复通知、测试通知接口。
- 企业微信/钉钉 Markdown、飞书卡片、Telegram HTML 和通用 JSON 展示剩余额度、窗口重置时间、主动重置次数及到期时间。
- 通知异步投递，检查平台回执，拒绝重定向，不影响额度保护。

### 升级与插件库

1. 备份 CPA 配置、原动态库及插件用户数据。
2. 刷新现有插件库，升级 `Codex Quota Reserve` 到 `0.2.0`。CPA 缓存最新版本查询一小时；仍显示旧版本时等待缓存过期，或重启 CPA 再刷新。
3. 核对下载 ZIP 的 SHA256，重启 CPA 后检查活动插件版本。
4. 需要实际停用账号时，开启“达到预留线时在 CPA 中停用账号”；原有预留保护配置继续保留。
5. 在插件内填写通知地址，发送测试通知，再按需要开启通知和定时报告。

额度估算不是上游精确硬额度保证。通知为尽力投递，不承诺必达。
带签名的钉钉机器人仍需外部签名网关。
真实账号和外部机器人投递需要部署后验收；本次测试不修改生产 CPA。
