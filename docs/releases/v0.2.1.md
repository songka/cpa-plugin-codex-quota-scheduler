# Codex Quota Reserve v0.2.1

## Changes

- Stop sending Webhook notifications for quota-cycle reset and history-only events.
- Send automatic messages only for scheduling participation transitions and due scheduled usage reports.
- Deduplicate active-reset recovery so a recovered account produces one start notification after fresh quota and CPA admission are both confirmed.
- Keep multi-account notifications together when the provider payload remains within its limit; split only between complete account cards when necessary.
- Synchronize saved plugin settings into CPA's `plugins.configs.codex-quota-reserve` entry without overwriting host metadata or private Webhook credentials.
- Evaluate live concurrency and unobserved request budgets before selecting an account, skipping blocked accounts in favor of safe alternatives.
- Publish exact rejection markers immediately; show missing Codex quota records temporarily without modifying CPA's authoritative account roster.
- Recover concurrency on request completion without waiting for a quota poll. Keep estimated consumption charged until fresh quota evidence arrives, including active-reset recovery.

## Host Limitation

CPA v8.0.27 returns an after-auth interceptor termination directly to the client. A request already rejected by this race guard receives HTTP 503 with `Retry-After: 1`; the plugin cannot reroute that same request through this API. Subsequent scheduler picks skip blocked accounts. Selection-time exclusion minimizes this race, but does not eliminate simultaneous selection or explicitly pinned requests.
