# Codex Quota Reserve v0.2.2

## 修复

- 可归属账号的上游 503/429/529 等临时失败进入 30 秒冷却，状态页显示原因，后续选号跳过；严格保护的嵌套重试可以从 A 切到安全的 B。
- 配额刷新不会覆盖并发请求刚写入的账号冷却标记，冷却到期无需等待轮询即可恢复选择。
- 宿主 YAML 显式配置逐字段优先于历史数据；未传字段、私有通知地址和账号注释保留。损坏数据及保存失败不再静默忽略。
- 明确执行前拒绝的最后一次准入预算可回滚；被保护线拒绝的新尝试不会错误退还之前已执行尝试的预算。
- Reserve 开启且配额刷新间隔超过 5 分钟时，状态页和配置日志给出警告。

## 兼容与边界

- 要求 CLIProxyAPI v8.0.27；发布 Linux glibc AMD64/ARM64 包及 SHA256。
- 原插件库 `registry.json` 地址不变，宿主通过最新正式 GitHub Release 发现更新；已有 CPA 最新版本缓存可能延迟一小时。
- 503、网络失败、超时并不证明上游零消耗，仍保留保守估算；这不是精确的配额计费。
- CPA v8.0.27 的 after-auth 终止为终端响应：选号阶段可跳过已饱和账号，极少数选号后竞态或外部固定账号仍可能返回本地 503，不能在插件内重选同一请求。
- 恢复围栏不是配额写入过滤器；相等时间戳的合法配额可入库，陈旧耗尽数据不能立即把恢复账号再次停用。
- 未修改生产 CPA 配置，也未发送真实 Webhook 或模型请求。逐项验收见 `docs/reserve-audit-2026-10-15.md`。
